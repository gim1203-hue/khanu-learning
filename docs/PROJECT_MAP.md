# Project file and component guide

This guide maps the source files to their purpose so the project can be explored or extended in VS Code.

## Top-level files

| Path | Purpose |
|---|---|
| `package.json`, `package-lock.json` | Root commands and reproducible Node dependencies |
| `.env.example` | Backend environment-variable template; copy it to an ignored `.env` for local use |
| `.gitignore` | Excludes secrets, generated bundles, model weights, and runtime data |
| `scripts/build-pages.mjs` | Sets the correct base path and static-demo mode for GitHub Pages builds |
| `scripts/generate-capstone-docx.py` | Generates the companion Word capstone document from the completed project outline |
| `.github/workflows/pages.yml` | GitHub Actions build and Pages deployment workflow |
| `README.md` | Main setup and project entry point |
| `Khanu Learning Capstone Documentation.docx` | Capstone narrative document |

## Frontend (`frontend/`)

| Path | Responsibility |
|---|---|
| `frontend/index.html` | Document shell, metadata, and app mount point |
| `frontend/vite.config.js` | React plugin, local API proxy, and deployment base path |
| `frontend/src/main.jsx` | Mounts React, routing, auth context, and styles |
| `frontend/src/App.jsx` | Catalog, matching form, navigation, session dashboard, theme, and primary UI state |
| `frontend/src/styles/app.css` | Responsive visual system, robot animation, cards, modals, and themes |
| `frontend/src/context/AuthContext.jsx` | Full-stack session state and browser-demo profile state |
| `frontend/src/services/api.js` | Routes requests to Express or the static browser demo |
| `frontend/src/services/demoCatalog.js` | Demo tutor/session catalog and category list for Pages |
| `frontend/src/services/localMatching.js` | Browser-local transparent recommendation ranking |
| `frontend/src/services/localDemoApi.js` | Browser-only demo profiles and bookings in local storage |
| `frontend/src/services/localDemo.test.js` | Pages-mode matching and booking checks |
| `frontend/src/components/Robot.jsx` | Animated Khanu robot and color customization |
| `frontend/src/components/ServiceCard.jsx` | Reusable catalog and recommendation card |
| `frontend/src/components/AuthModal.jsx` | Backend account form or password-free browser-demo profile form |
| `frontend/src/components/BookingModal.jsx` | Future appointment form and validation feedback |

## Backend (`backend/src/`)

| Path | Responsibility |
|---|---|
| `server.js`, `dev.js`, `app.js` | Production/development server startup and Express middleware |
| `routes/api.js` | Endpoint declarations, auth requirement, and rate limits |
| `controllers/authController.js` | Registration, login, and current user |
| `controllers/serviceController.js` | Catalog listing and filters |
| `controllers/bookingController.js` | Booking creation, listing, ownership, and cancellation |
| `controllers/aiController.js` | Validates recommendation requests |
| `services/catalog.js`, `data.js` | Catalog and in-memory demo data access |
| `services/recommendation.js` | Shared conceptually with Pages matcher; ranks catalog and optionally asks local LLM for wording |
| `middleware/auth.js` | JWT validation and protected-route user loading |
| `config/database.js` | Mongo connection, seed initialization, and explicit memory fallback |
| `models/User.js`, `models/Service.js`, `models/Booking.js` | Mongoose document schemas |
| `api.test.js`, `services/recommendation.test.js` | Authentication, booking lifecycle, route, and matcher tests |

## Documentation

The `docs/` directory explains requirements, solution design, data flow, API routes, setup, deployment boundaries, privacy, user workflows, test strategy, and the full-stack-to-Pages split. The production `frontend/dist/` directory is generated by build commands and is intentionally ignored by Git; the Pages workflow uploads it as an artifact.
